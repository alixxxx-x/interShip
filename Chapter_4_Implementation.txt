CHAPTER 4: SYSTEM IMPLEMENTATION

4.1 OVERVIEW
This chapter presents the results of the technical implementation of the "InterShip" project. It covers the proposed system architecture, the hardware and software resources utilized, database schema details, and key implementation examples, followed by a presentation of the main user interfaces.

4.2 PROPOSED SYSTEM ARCHITECTURE
The system follows a modern Client-Server architecture based on the Single Page Application (SPA) model. This ensures a clean separation between the frontend presentation and the backend business logic.

4.2.1 Presentation Tier (Frontend)
Developed using React 19 and Vite, this tier manages the user interface and interactions. It uses Tailwind CSS for responsive design and Radix UI primitives for accessible components. Communication with the backend is handled via asynchronous HTTP requests using the Axios library.

4.2.2 Application Tier (Backend)
The logic is powered by Django 6.0 and Django REST Framework (DRF). This tier handles:
- User authentication and authorization (JWT-based).
- Business logic for internship applications and validations.
- Real-time notifications and direct messaging.
- Integration with external services (AI and PDF generation).

4.2.3 Data Tier (Persistence)
The relational database stores all system entities. While SQLite is used for development, the system is fully compatible with PostgreSQL for production environments. Media files (CVs, images) are managed through Django's storage system.

4.4 DATA AND PROCESSING IMPLEMENTATION EXAMPLES
4.4.1 Admin Analytics Logic (Processing Example)
The system calculates real-time placement rates using Django's ORM aggregation to provide administrators with accurate platform metrics.

```python
# Backend logic for calculating student placement stats
def get_stats(self, request):
    total_students = User.objects.filter(role=User.Role.STUDENT).count()
    placed_students = Application.objects.filter(
        status=Application.Status.ACCEPTED,
        is_validated_by_admin=True
    ).values('student').distinct().count()
    
    unplaced_students = total_students - placed_students
    placement_rate = (placed_students / total_students * 100) if total_students > 0 else 0
    return Response({
        "total": total_students,
        "rate": placement_rate
    })
```

4.5 DATABASE STRUCTURE AND ENTITIES
The database schema consists of several interconnected tables, each designed to manage a specific aspect of the internship workflow.

1. USER (Base Table)
   - Fields: id, email, username, password, role (STUDENT, COMPANY, ADMIN), profile_picture.
   - Role: Handles core authentication and user identification.

2. STUDENT (Inherits from User)
   - Fields: user_ptr_id, university_id, wilaya, phone.
   - Role: Stores academic-specific information for students.

3. COMPANY (Inherits from User)
   - Fields: user_ptr_id, name, logo, description, location, website, company_field.
   - Role: Manages organization profiles and branding.

4. INTERNSHIPOFFER
   - Fields: id, title, description, company_id (FK), status (DRAFT, OPEN, CLOSED), location, type, duration, number_of_places.
   - Role: Stores available internship opportunities posted by companies.

5. APPLICATION
   - Fields: id, student_id (FK), internship_id (FK), status (PENDING, ACCEPTED, REJECTED), application_date, is_validated_by_admin.
   - Role: Tracks the relationship and status of candidate applications.

6. SKILLS
   - Fields: id, name, skill_level (BEGINNER, INTERMEDIATE, ADVANCED), internship_id (FK).
   - Role: Categorizes technical requirements for offers and user profiles.

7. DIGITALCV
   - Fields: id, student_id (FK), first_name, last_name, email, skills, experience, education, cv_file, date_of_birth.
   - Role: Centralized repository for student professional data.

8. NOTIFICATION
   - Fields: id, recipient_id (FK), notification_type, message, is_read, created_at.
   - Role: Logs and delivers real-time alerts to stakeholders.

9. MESSAGE
   - Fields: id, sender_id (FK), recipient_id (FK), content, is_read, created_at.
   - Role: Handles direct peer-to-peer communication between admin and companies.
